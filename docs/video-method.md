# Presenter video generation — method

This study asks whether the RTX PRO 4500 Blackwell system can turn one still
portrait and one English speech track into useful presenter footage. It does
not test cinematic text-to-video. The target is deliberately narrower: a host,
guest or character speaking inside a composited discussion, explainer or
vertical story.

Each result is one deterministic run on the same machine described in
[Configuration](machine.md). The source portraits were generated by FLUX.2 Dev
32B Q8_0 through AI-Lab and remain unchanged between compatible models. The
speech tracks come from the repository's English TTS pass and are trimmed to
six seconds. Models and transient runtime files stay in benchmark storage; no
video model is promoted to core by these tests.

## Cases

| Case | Still image | Speech source | Production question |
|---|---|---|---|
| Documentary host | Photorealistic male host, locked studio framing | Qwen3-TTS CustomVoice, Aiden, American documentary narration | Can a recurring presenter retain identity and speak naturally? |
| Roundtable guest | Photorealistic Black woman researcher, locked studio framing | Qwen3-TTS VoiceDesign, contemporary southern-British editorial narration | Can a guest tile remain stable while showing restrained expression? |
| Animated storyteller | Older fox in polished 3D-animation style | Qwen3-TTS VoiceDesign, older Irish storyteller | Can the same face-driven route animate a non-human character? |

The exact portrait prompts, intended motion descriptions and fixed seeds are
in [`harness/video`](../harness/video/). The spoken texts remain in the English
TTS manifest so the audio and video studies use the same material.

### Audio scope

The speech files are fixed control inputs for animation and synchronization.
They were not selected or scored for casting against the visible character:
perceived gender, age, pitch, accent, timbre and persona fit are outside this
video study. This separation prevents a voice-character mismatch from being
misreported as a video-model failure. In a production workflow, voice casting,
synthesis or conversion and audio processing happen separately; the resulting
final speech track is then supplied to the audio-driven animation or lip-sync
stage. LivePortrait Animals is motion-driven rather than audio-driven and is
not included in the synchronization comparison.

InfiniteTalk needs two compatibility changes on this Blackwell runtime. The
quantization extension is compiled against the installed CUDA 13 toolchain,
and FlashAttention/xFormers calls whose published kernels reject compute
capability 12.0 use PyTorch scaled dot-product attention instead. The source
patch is preserved in [`harness/video/patches`](../harness/video/patches/).
This fallback is expected to be slower than a native Blackwell attention
kernel and is therefore part of the practical result.

JoyVASA and LivePortrait Animals use the same reference PyTorch XPose fallback
because the published custom extension cannot be built against this CUDA
13 host and the CUDA 12.8 PyTorch wheel. LivePortrait reuses the complete
checkpoint tree already present under benchmark storage; it does not create a
second or partial model copy.

HunyuanVideo-Avatar runs with PyTorch scaled dot-product attention because the
published FlashAttention dependency is not available for this Blackwell
runtime. Transformers is pinned to 4.45.2: newer releases reject the upstream
single-image-token LLaVA preparation with the repository's known 576-feature
mismatch. The public report records the measured configuration but does not
redistribute the generated file or the source patch; the model licence excludes
the European Union, where this test machine is located.

Wan2.2-S2V is loaded by ComfyUI directly from the complete FP8-scaled model
tree in benchmark storage. The published checkpoint carries ComfyUI
quantization metadata, so the native loader is part of the tested
configuration. A preliminary DiffSynth compatibility experiment produced a
valid container with visually corrupted frames and is excluded from the
viewing set; the corrective native run is the reported result. Its exact API
workflow is stored as [`wan22-s2v-comfyui-api.json`](../harness/video/wan22-s2v-comfyui-api.json).

## Measurements

Wall time covers model initialization, generation and output encoding. Peak
GPU memory is polled through `nvidia-smi`; process resident memory is polled
from the operating system. These are observed peaks, not allocator guarantees.

An InsightFace pass samples every fifth frame and reports:

- face detection rate;
- mean and minimum cosine similarity to the source portrait;
- normalized face-centre and face-area variation;
- Laplacian sharpness;
- mean pixel change between sampled frames.

The identity cosine values compare each generated face with its own source.
They are useful for comparing two treatments of the same portrait, not as a
universal quality threshold. Low frame change means stability, but it can also
mean insufficient expression.

The official SyncNet evaluator reports audio-video offset and confidence where
its detector accepts the clip. This is an automatic lip-sync signal, not a
claim about natural expression, voice-character suitability or overall
production quality.

## Automatic verdicts

The report assigns practical automatic verdicts from successful generation,
face coverage, identity retention, synchronization and measured resource cost.
The accompanying video page carries no viewing score: it presents the input
and output so each reader can inspect motion, lip shape and visual artifacts
directly.
